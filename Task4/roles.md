# Kubernetes RBAC — роли и группы пользователей

Модель доступа построена по принципу минимальных привилегий. Доступ к Kubernetes разделён по организационным функциям: просмотр ресурсов, управление бизнес-сервисами и инфраструктурой, а также привилегированные операции службы безопасности.

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| `cluster-readonly` | Только чтение ресурсов кластера: `get`, `list`, `watch`. Нет права создавать, изменять или удалять ресурсы. | `developers`, `analysts` |
| `namespace-operator` | Управление ресурсами бизнес-сервисов в выделенном namespace: Pods, Deployments, Services, ConfigMaps, Jobs, Ingress. Разрешены `get`, `list`, `watch`, `create`, `update`, `patch`, `delete`. Доступ к Secrets ограничен чтением и не предоставляется этой роли. | `developers` |
| `cluster-operator` | Администрирование Kubernetes-кластера: управление namespace, nodes, workloads и сетевыми ресурсами. Разрешены `get`, `list`, `watch`, `create`, `update`, `patch`, `delete` для ресурсов, необходимых для эксплуатации кластера. | `platform-admins` |
| `security-admin` | Привилегированный доступ для службы безопасности. Просмотр Secrets, ServiceAccounts, Roles, ClusterRoles, RoleBindings, ClusterRoleBindings, а также аудит конфигурации доступа. Изменение RBAC не предоставляется по умолчанию. | `security-team` |
| `rbac-admin` | Полное управление RBAC: Roles, ClusterRoles, RoleBindings и ClusterRoleBindings. Используется только для администрирования модели доступа. | `security-admins` |

## Организационная модель

### `analysts`

Имеют только права чтения. Они могут получать информацию о состоянии ресурсов Kubernetes, но не могут изменять конфигурацию.

### `developers`

Могут просматривать ресурсы кластера и управлять бизнес-приложениями в выделенных namespace. Они не должны получать доступ к Secrets и административным ресурсам всего кластера.

### `platform-admins`

Отвечают за эксплуатацию Kubernetes. Получают права, необходимые для настройки и обслуживания инфраструктуры.

### `security-team`

Получает привилегированный доступ для контроля безопасности. В частности, группа может просматривать Secrets и настройки RBAC, но не получает права изменять RBAC.

### `security-admins`

Отдельная ограниченная группа, отвечающая за изменение Kubernetes RBAC. Доступ к этой группе должен предоставляться только уполномоченным администраторам безопасности.

## Принципы

- Используется принцип **минимальных привилегий**.
- Пользователи не получают `cluster-admin` без необходимости.
- Доступ разработчиков к бизнес-сервисам ограничивается namespace.
- Secrets не доступны обычным разработчикам.
- Привилегированные действия выделены в отдельную группу.
- Права на изменение RBAC отделены от права просмотра Secrets.
- Для рабочих namespace рекомендуется дополнительно использовать `ResourceQuota`, `LimitRange` и `NetworkPolicy`.
